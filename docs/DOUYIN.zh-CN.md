# 抖音演示方案（脚本草案，非已验收成果）

## 核心钩子（0–3 秒）
“我让 Codex 当老板，ChatGPT 网页当员工。任务完成后，它自己把结果发回 Codex。”

## 画面（35–45 秒）
1. **0–3s**：左右双屏，Codex 发起任务，网页子 Chat 接收；突出任务编号。
2. **3–10s**：先展示模式 B：Codex 总控派任务给网页 Chat；右侧显示任务进度。不要伪造计时或额度节省数字。
3. **10–19s**：子 Chat 完成，展示脱敏的 `reason-network send … -` 与回执字段（任务编号、状态、证据）。
4. **19–27s**：Codex App 总控出现消息，核对证据、ACK；再决定下一步。仅在真实现场验证通过后，称为“自动回到原会话”。
5. **27–35s**：切换模式 A：Chat 总控派给另一个 Chat，结果回来继续安排。
6. **35–42s**：解释监控：30 分钟 Luna Max 检查；没有可验证失败证据不会乱 Retry。
7. **42–45s**：“我把这套核心闭环单独做成 ChatBridge Lite，仓库提供 Remote Desktop Commander 快速连接指引、回调设计和测试记录。”

## 发布前的事实门槛

- 一镜到底保留原始时间戳/任务 ID；截图必须遮盖本地用户、机器地址、Reason Network 私人 session、凭据、GitHub 私有路径。
- 不说“无限免费”“永不掉线”“100% 无人值守”；说“减少 Codex 亲自执行的任务量”。
- 不展示一条实际上未投递却声称已完成的回调。
- 对比节省 Codex 用量时，必须同任务、同验收口径实测；没有数据就只展示工作分配机制。
- 第一条视频的成功指标建议先看完整播放率、收藏率、评论里的真实安装问题，不预设爆款。
